# Практическая работа №2 — система заказов и доставки

[← К README](../README.md) · [Работа №1](practical-work-1-summary.md) · **Работа №2** · [Работа №3](practical-work-3-summary.md)

## Цель работы

Расширить складское приложение подсистемой заказов, покупателей, доставки и скидок, применив паттерны «Легковес», «Стратегия», «Прокси» и «Наблюдатель». Адаптировать требования, сформулированные для C++, к Java и предоставить демонстрационный Swing-интерфейс.

## Что было сделано

### Покупатели и заказы

- Реализован `Customer` с идентификатором, именем, регионом и бонусным балансом.
- Реализован `OrderItem`, который сохраняет снимок названия, цены, веса и количества товара на момент оформления.
- Реализован `Order` с позициями, статусом, доставкой, скидками, подарками и итоговой стоимостью.
- Добавлены операции добавления и удаления позиций с синхронным изменением складского остатка.
- После назначения доставки или применения скидки состав заказа изменять нельзя, чтобы не нарушить рассчитанную стоимость.
- Реализованы допустимые переходы между статусами `PENDING`, `PAID`, `SHIPPED`, `DELIVERED`, `CANCELLED`.
- Реализован `Comparable<Order>`: `compareTo(...)` сравнивает заказы по итоговой стоимости и идентификатору.
- Переопределён `toString()` для компактного вывода состояния заказа.

### Управление заказами

- `OrderManager` хранит заказы в `Map<Long, Order>` и покупателей в множестве идентификаторов.
- Перед созданием заказа проверяются позиции, остатки и лимит активных заказов покупателя.
- При создании заказа товар списывается со склада.
- При отмене заказа количество товаров восстанавливается.
- При оплате итоговая сумма заказа добавляется к обороту.
- Количество активных заказов вычисляется по текущим статусам, поэтому отменённый или доставленный заказ автоматически перестаёт занимать лимит.

Лимит использует явный подсчёт активных заказов покупателя:

```java
public int getActiveOrderCount(Customer customer) {
    if (customer == null) {
        throw new IllegalArgumentException("Customer cannot be null");
    }

    int count = 0;
    for (Order order : orders.values()) {
        OrderStatus status = order.getStatus();
        if (order.getCustomer().getId() == customer.getId()
            && (status == OrderStatus.PENDING
                || status == OrderStatus.PAID
                || status == OrderStatus.SHIPPED)) {
            count++;
        }
    }
    return count;
}
```

### Паттерн «Легковес»

- Создан неизменяемый `ProductType` с категорией, базовым весом и базовой ценой.
- Статический пул переиспользует типы с одинаковым набором характеристик.
- `Product` хранит ссылку на общий `ProductType`, а не дублирует категорию и базовый вес.
- Клон товара получает новый идентификатор, но разделяет безопасный неизменяемый тип.

### Паттерн «Стратегия»: доставка

Создан интерфейс `Delivery`:

```java
double getCost(Order order);
String getEstimatedTime();
boolean isAvailable(Order order);
```

Реализованы стратегии:

- `CourierDelivery` — стоимость 500, срок 1–2 дня, ограничение 20 кг;
- `PickupDelivery` — бесплатно, срок 1–3 дня, без ограничения веса;
- `PostDelivery` — стоимость 200, срок 5–10 дней, ограничение 10 кг.

`Order.assignTo(...)` назначает выбранную стратегию после проверки доступности.

### Паттерн «Стратегия»: скидки

Создан интерфейс `Discount` с методом `apply(Order)` и реализации:

- `PercentDiscount` уменьшает стоимость товаров на 10%;
- `CashbackDiscount` начисляет 5% итоговой суммы на бонусный баланс;
- `FreeDeliveryDiscount` обнуляет стоимость доставки;
- `GiftDiscount` добавляет бесплатный товар, не увеличивая цену заказа.

Заказ хранит список применённых скидок, а `applyDiscount(...)` является единой точкой их применения.

### Паттерн «Прокси»

`DeliveryProxy` реализует `Delivery`, хранит реальную стратегию доставки и:

- проверяет заказ и регион покупателя;
- проверяет доступность реальной доставки;
- делегирует расчёт стоимости;
- кэширует стоимость по идентификатору и версии состояния заказа;
- возвращает кэшированное значение при повторном запросе;
- автоматически пересчитывает стоимость после изменения состава, доставки, скидок или статуса заказа.

Дополнительно создан `LoggingProxy` с источниками:

- `ORDER`;
- `DELIVERY`;
- `DISCOUNT`;
- `MANAGER`.

Он журналирует начало, успешное завершение и ошибку операции, не скрывая исходное исключение.

### Паттерн «Наблюдатель»

- Созданы интерфейсы `Observer` и `Observable`.
- Создан неизменяемый `OrderEvent` с идентификатором заказа, старым и новым статусом и `Instant timestamp`.
- `Order` уведомляет подписчиков после успешной смены статуса.
- `OrderManager` подписывается на созданные заказы и обновляет оборот или возвращает остатки.
- При уведомлении используется копия списка наблюдателей, поэтому подписчики могут безопасно менять подписки во время обработки события.

## Java-аналоги требований C++

Java не поддерживает пользовательскую перегрузку операторов, поэтому применены именованные операции:

| Требование C++ | Реализация Java |
|---|---|
| `order + discount` | `order.applyDiscount(discount)` |
| `delivery << order` | `order.assignTo(delivery)` |
| `order1 < order2` | `order1.compareTo(order2) < 0` |
| `ostream << order` | `order.toString()` |
| `shared_ptr<Delivery>` | обычная ссылка `Delivery`, управляемая сборщиком мусора |
| `const vector&` | неизменяемое представление `Collections.unmodifiableList(...)` |
| чисто виртуальный метод | метод Java-интерфейса |

## Демонстрационный интерфейс

Главное окно разделено на две вкладки:

- **Склад** — управление складами и товарами из первой работы;
- **Заказы** — управление покупателями и заказами.

Во вкладке заказов доступны:

1. создание покупателя;
2. создание заказа из товара текущего склада;
3. добавление и удаление позиций;
4. выбор доставки через `DeliveryProxy`;
5. применение одной или нескольких скидок;
6. смена статуса;
7. просмотр подробностей, бонусного баланса и оборота.

Ошибки модели перехватываются на границе UI и показываются через `JOptionPane`, поэтому приложение не завершается аварийно.

## Демонстрационные сценарии

### Сценарий 1 — создание заказа и процентная скидка

1. На складе выбирается товар.
2. `OrderManager` проверяет остаток и создаёт заказ.
3. Количество товара уменьшается.
4. Применяется `PercentDiscount`.
5. Цена товарной части заказа уменьшается на 10%.

### Сценарий 2 — выбор доставки

1. Выбирается курьер, почта или самовывоз.
2. Стратегия оборачивается в `DeliveryProxy`.
3. Прокси проверяет доступность и рассчитывает стоимость.
4. Повторный запрос получает значение из кэша.
5. После изменения заказа версия состояния меняется, и прокси автоматически пересчитывает стоимость.

### Сценарий 3 — оплата

1. Статус меняется с `PENDING` на `PAID`.
2. `Order` создаёт `OrderEvent`.
3. `OrderManager` получает событие и увеличивает оборот.

### Сценарий 4 — несколько скидок

Скидки применяются последовательно и сохраняются в заказе. Процентная скидка изменяет цену, бесплатная доставка влияет только на доставку, кешбэк изменяет бонусный баланс, а подарок хранится отдельно от оплачиваемых позиций.

### Сценарий 5 — отмена

1. Статус меняется на `CANCELLED` из `PENDING` или `PAID`.
2. Наблюдатель возвращает количества исходным товарам.
3. Заказ больше не считается активным и освобождает лимит покупателя.

## Результат

Получено Swing-приложение, объединяющее склад и систему заказов. Модель отделена от UI, стратегии доставки и скидок взаимозаменяемы, прокси добавляет контроль и кэширование, наблюдатель связывает изменение статуса со статистикой, а легковес сокращает дублирование данных типов товаров.
